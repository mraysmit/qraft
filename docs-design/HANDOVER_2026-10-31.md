## 2. How the owner wants the work done

These come from `AGENTS.md`, `docs/TESTING.md` and the owner's standing instructions. Break them and the owner will notice.

- **Strict test-first.** A failing test is written and run, and seen to fail for the right reason, before the production code for it exists. A test that cannot compile is not a red test: add a stub that compiles and does nothing, and see the assertion fail. Do not ask whether to write tests first.
- **Do not commit.** The owner commits and pushes their own work. Never add assistant or AI attribution to commits, pull requests, code or documentation.
- **Verify on Jenkins when it is reachable, otherwise run every suite locally against Docker Desktop** (section 5), without stopping to ask. Never remove Docker volumes without listing them and getting the owner's word.
- **Run builds in a visible console**, through `Tee-Object` into `logs/`, never hidden in the background.
- **Logs are part of the result.** A run is accepted only after the retained Maven output, application logs, helper-subprocess logs and Docker archives have been read. Any ERROR, or any stack trace at any level, that is not flagged `*** INTENTIONAL ERROR: ... ***` or `*** INJECTED FAILURE: ... ***` is a defect to find and fix. Never filter it, lower its level, or change a log's level or frequency unless asked. See `docs/TESTING.md`, "Intentional error flags and log auditing".
- **Declare an intentional error only with evidence.** Establish what the test did that caused it, give it the narrowest definition that matches (a definition can also name the exception the event carries), say why in a comment beside the declaration, and declare it only in the class where it was seen.
- **A race or an intermittent failure is a defect.** Find the cause and check production for the same race. Do not retry it away; the owner had the image-build retry removed for this reason.
- **Compare with industry practice.** The owner asks that designs be checked against HashiCorp Consul (and its `hashicorp/raft`); quote the source when you do.
- **Clean code, no loose ends.** Resolve inconsistencies in code and documents when found. When a change removes a state transition, first list every observable effect the old transition had, mark each removed or kept on purpose, and write a failing test for each effect that must survive (Pre-Vote lost a cleared-leader effect this way; see design section 14.10).
- **Task lists and handovers** live in `docs-design/` with the date of their last change in the file name. Rename one on the day it changes, update every reference (a list renamed for a link counts as changed, so lists that link each other are renamed together), and archive a finished list to `docs/archive/` without asking.
- **Words:** Qraft has only "server mode" and "client mode". Do not use the two retired words for the components.
- **Files:** every new Java file has the Apache header and an `@author`, `@since` and `@version` Javadoc. The working tree is CRLF; normalise files written by tools (on Windows, `sed -i` writes LF: check with `file`, fix with `unix2dos`). No Mockito. Time and sleeping go through injected clocks and timer helpers in tests. PIT is shelved.

The client retries `node_name_reserved` after its registration backoff. A client that lost its name to another learns it from its next heartbeat (409 `registration_superseded`, distinct from an out-of-order `stale_heartbeat`) and registers again, so it takes the name back once the other node is unreachable; while its node is not registered it sends no service write, and a service refused with `node_name_reserved` is sent again on the next pass. `GET /v1/catalog/nodes` lists each node's `id`. It binds `client.bindAddress`, `127.0.0.1` by default as Consul's `client_addr` (an IP address; a host name is refused), and logs `Local API started: protocol=http, address=...`; the runtime lifecycle reports every listener's address in both modes.   - **TTL status:** `PUT /v1/client/check/pass/{checkId}`, `warn` and `fail`, with an optional `note`, and `update/{checkId}` with `status` and `output`. An unknown check answers 404 `check_not_found`, a check that takes no status 400 `check_not_ttl`, and one not running yet, before the node registers, 503 `check_not_running`, retryable.
  - **Maintenance:** `PUT /v1/client/maintenance` and `PUT /v1/client/service/maintenance/{serviceId}`, with `enable` and an optional `reason`. As in Consul it is a check of its own (`MaintenanceCheck`), which the service declares, kept across a restart, and enabling it again keeps the first reason. Unlike Consul's critical check it reports the server's `maintenance` status, and it is not required, so it never holds readiness back. - **Client list Phase 6, client information** (2026-10-31, in `841b6f1`), test first, checked against Consul's `agent_endpoint.go`. 19 of the 66 tests in the affected classes were seen red on stubs.
  - **`GET /v1/client/self`** (`LocalClientRoutes`): node name and ID, version, settings, last server contact and each readiness condition (`ReadinessPolicy.Conditions`). Settings are named one by one, so a secret added later is not shown by default; Consul sanitizes its whole configuration instead.
  - **`GET /v1/client/members`** is a forwarded read of `/v1/catalog/nodes`, because Qraft has no gossip pool, through the new `HttpCatalogClient.forwardRead`, which passes the answer on as it came and under the caller's request ID. With no server to ask it answers 503 `no_server_reachable`, retryable. Unlike Consul's gossip list, it has no answer without a server, lists only clients, and does not show a node that left.
  - **`PUT /v1/client/leave`** answers once the client has left the catalog or tried to within its shutdown bound, with `deregistered` saying which, and then the client shuts down and its process exits with code 0 (`ClientLeaveEndToEndTest`, in a JVM of its own). The handler cannot wait for the whole shutdown, which waits for the handler, so `QraftClient.shutdown` now has `depart` as its first half. The runtime learns from `QraftClient.left()`, a future, so a leave that comes before the lifecycle exists is not missed. A Consul client also exits when its leave fails, because `Client.Leave` logs the failure and returns no error. A client that could not deregister is then treated as one that crashed: its checks expire, its node is marked unreachable after `nodeTtlMs`, and the catalog keeps both until `nodeReapAfterMs`, 72 hours by default. API registrations stay in the data directory, as Consul's do. Consul treats a leave as "a permanent intent" and needs an explicit join to come back; a client always has its server URLs, so its next start registers it again.
- **Client list Phase 6A, a dead node's services in discovery** (2026-10-31, uncommitted), test first, after Consul's `?passing`, whose source is in the client list. 4 of the 48 tests in the affected classes were seen red, on their assertions.

Check results and stored health do not change, and a returning heartbeat restores the instance with no new observation. An instance whose node has no entry is decided by its checks. `/v1/catalog/service/{name}` still lists the instance until the node is reaped.
  - **Each health entry carries `nodeStatus`,** null with no node entry, so that an unfiltered answer explains why an instance with passing checks is not in `?passing`. This field is an addition of Qraft's: Consul's answer shows `serfHealth` among the checks instead.
