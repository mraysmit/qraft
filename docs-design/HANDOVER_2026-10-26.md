## 2. How the owner wants the work done

These come from `AGENTS.md`, `docs/TESTING.md` and the owner's standing instructions. Break them and the owner will notice.

- **Strict test-first.** A failing test is written and run, and seen to fail for the right reason, before the production code for it exists. Do not ask whether to write tests first.
- **Do not commit.** The owner commits and pushes their own work. Never add assistant or AI attribution to commits, pull requests, code or documentation.
- **The main verification runs on Jenkins**, which is started once the work is pushed. Local runs are for small checks only. Never remove Docker volumes without listing them and getting the owner's word.
- **Logs are part of the result.** A run is accepted only after the retained Maven output, application logs, helper-subprocess logs and Docker archives have been read. Any ERROR, or any stack trace at any level, that is not flagged `*** INTENTIONAL ERROR: ... ***` or `*** INJECTED FAILURE: ... ***` is a defect to find and fix. Never filter it, lower its level, or change a log's level or frequency unless asked. See `docs/TESTING.md`, "Intentional error flags and log auditing".
- **A race or an intermittent failure is a defect.** Find the cause and check production for the same race. Do not retry it away.
- **Clean code, no loose ends.** Resolve inconsistencies in code and documents when found. When a change removes a state transition, first list every observable effect the old transition had, mark each removed or kept on purpose, and write a failing test for each effect that must survive (Pre-Vote lost a cleared-leader effect this way; see design section 14.10).
- **Task lists** live in `docs-design/` with the date of their last change in the file name. Rename a list on the day it changes, update every reference, and archive a finished list to `docs/archive/` without asking.
- **Words:** Qraft has only "server mode" and "client mode". Do not use the two retired words for the components.
- **Files:** every new Java file has the Apache header and an `@author`, `@since` and `@version` Javadoc. The working tree is CRLF; normalise files written by tools. No Mockito. Time and sleeping go through injected clocks and timer helpers in tests.

## 3. The uncommitted change set: client list, Phase 1

The server's service and check write routes left `/v1/client/*`, which now belongs to the client's local API (a later phase), for the catalog paths:

- `PUT /v1/catalog/register`: `service` beside or instead of `node`; at least one is required. The body is checked as a whole before anything is replicated; then the node is committed, then the service. A service the catalog rejects after the node was registered answers 409 `registration_rejected`, the node stays, and the client's retry repeats both idempotently.
- `PUT /v1/catalog/deregister`: `{"serviceId": "web"}` removes that service and keeps the node; `{}` removes the node and everything on it. The service ID must be a non-blank string, so a missing or blank value cannot remove the node by accident.
- `PUT /v1/catalog/check/observe`: the old health observation route, same body and answers.
- The three `/v1/client/service/register`, `/v1/client/service/deregister/{id}` and `/v1/client/check/observe` routes and handlers are removed. `HttpCatalogClient` sends and reads the new shapes.

**Tests.** New: `HttpApiServerCatalogServiceRoutesTest` (12). Changed to the new protocol: `HttpApiServerTest`, `HttpCatalogClientTest`, `QraftClientTest` (through `NodeAnswerHelper.dispatching`, which sends a request on a shared route to the handler of the half its body carries), `ClientServerContractTest` (a lookup and an observation against a real server were added), `ClientHealthPublicationTest`, `HealthPropagationEndToEndTest`, and the Docker helpers and classes that register services over raw HTTP. A local run of the client, server, state and contract packages ran 482 tests with no failures, but its logs were not audited and no Docker test was run.

**Documents updated:** design sections 12.1, 12.1.1, 12.1.2 and the opening note on `/v1/client/*`; the Consul plan; the admin interface plan; the client list's Phase 1 section.

**To close Phase 1:** commit and push, run the full Jenkins job, audit the logs, and record the build in `docs/JENKINS.md`. The Docker stage must run on a fresh image, since the Docker classes changed.

1. A required `client.dataDirectory` with a one-client-per-directory lock; a generated node ID kept in `node-id`; `client.id` becomes `client.nodeName`. The server's `ServerIdentity` code is shared through `common`.

## 5. Running things

- **JDK 27.** `JAVA_HOME` is `C:\Users\mraysmit\.jdks\openjdk-27-1`. A shell that defaults to JDK 25 gives wrong results.
- **Test groups.** The default build skips the `docker` and `e2e` groups. Run them with `-Dgroups=docker -Dtest.excludedGroups=` or `-Dgroups=e2e -Dtest.excludedGroups=`. In PowerShell, quote every `-D` argument, or `-Dtest.excludedGroups=` is split in two.
- **Docker tests** need `mvn package` first: a freshness guard checks that `target/qraft.jar` is current. They build their image once per run, with `docker compose build`, and a failed build is never retried (the retry for the daemon's "failed to prepare extraction snapshot" fault was removed on 2026-10-27). With no Jenkins reachable, run every suite locally against Docker Desktop.
- **The IDE** can leave stale class files that throw "Unresolved compilation problem". Delete the class files under `target/test-classes` and rebuild.
- **Jenkins** (`http://192.168.137.32:8080/job/Qraft/`) builds the pushed `main`. `.\.env\qraft-jenkins-build.ps1` starts a build, follows it, and saves the console and archived logs under `logs/jenkins/Qraft-<n>/`. On 2026-10-25 and 26 its start request timed out while Jenkins had in fact queued the build. Before starting again, ask Jenkins for the last build (`job/Qraft/api/json?tree=lastBuild[number,building]`) and follow that one. A build that fails before any test ran, at the checkout, is an infrastructure failure and says nothing about the code.
- **Auditing a build.** Count the ERROR lines in the console and in `archive/logs`, require that every one carries a flag, and check that no stack trace is unflagged. A flag on an exception header covers its trace. One known false positive for a simple checker: the `lock-contender` trace in `DockerDurableRestartTest` is flagged on its "Exception in thread" line.
