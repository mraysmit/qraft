## 2. How the owner wants the work done

These come from `AGENTS.md`, `docs/TESTING.md` and the owner's standing instructions. Break them and the owner will notice.

- **Strict test-first.** A failing test is written and run, and seen to fail for the right reason, before the production code for it exists. A test that cannot compile is not a red test: add a stub that compiles and does nothing, and see the assertion fail. Do not ask whether to write tests first.
- **Do not commit.** The owner commits and pushes their own work. Never add assistant or AI attribution to commits, pull requests, code or documentation.
- **Verify on Jenkins when it is reachable, otherwise run every suite locally against Docker Desktop** (section 5), without stopping to ask. Never remove Docker volumes without listing them and getting the owner's word.
- **Run builds in a visible console**, through `Tee-Object` into `logs/`, never hidden in the background.
- **Logs are part of the result.** A run is accepted only after the retained Maven output, application logs, helper-subprocess logs and Docker archives have been read. Any ERROR, or any stack trace at any level, that is not flagged `*** INTENTIONAL ERROR: ... ***` or `*** INJECTED FAILURE: ... ***` is a defect to find and fix. Never filter it, lower its level, or change a log's level or frequency unless asked. See `docs/TESTING.md`, "Intentional error flags and log auditing".
- **Declare an intentional error only with evidence.** Establish what the test did that caused it, give it the narrowest definition that matches (a definition can also name the exception the event carries), say why in a comment beside the declaration, and declare it only in the class where it was seen.
- **A race or an intermittent failure is a defect.** Find the cause and check production for the same race. Do not retry it away; the owner had the image-build retry removed for this reason.
- **Compare with industry practice.** The owner asks that designs be checked against HashiCorp Consul (and its `hashicorp/raft`); quote the source when you do.
- **Clean code, no loose ends.** Resolve inconsistencies in code and documents when found. When a change removes a state transition, first list every observable effect the old transition had, mark each removed or kept on purpose, and write a failing test for each effect that must survive (Pre-Vote lost a cleared-leader effect this way; see design section 14.10).
- **Task lists and handovers** live in `docs-design/` with the date of their last change in the file name. Rename one on the day it changes, update every reference (a list renamed for a link counts as changed, so lists that link each other are renamed together), and archive a finished list to `docs/archive/` without asking.
- **Words:** Qraft has only "server mode" and "client mode". Do not use the two retired words for the components.
- **Files:** every new Java file has the Apache header and an `@author`, `@since` and `@version` Javadoc. The working tree is CRLF; normalise files written by tools (on Windows, `sed -i` writes LF: check with `file`, fix with `unix2dos`). No Mockito. Time and sleeping go through injected clocks and timer helpers in tests. PIT is shelved.

## 4. What comes next

The ACL list, [`task-list-acl-and-tokens-2026-11-05.md`](task-list-acl-and-tokens-2026-11-05.md), started at the owner's word on 2026-11-04. Phases 1 and 2 are built; Phase 3, configuration and the first token, is next.

**First, the owner's decision on the open point at the end of Phase 1's record.** Phase 3 is the first phase that writes an ACL command, and a server from before ACLs decodes one as a no-op instead of stopping. Raise it before starting.

What Phase 3 starts from:

- **The bootstrap command exists.** `AclCommand.bootstrap(token, resetIndex)` creates the token once; after that the state refuses with `acl_bootstrapped`, its message naming the reset index, which `AclView.bootstrapIndex()` also answers, or `invalid_reset_index`. Consul's `initializeACLs` installs the management file's secret through a bootstrap while one is possible, and through a plain token creation after; Phase 3's leader does the same, with `installedFromFile` set.
- **The leader does what the state machine cannot.** It generates the accessor, stamps the creation time, checks that a secret is a UUID (`AclSecrets.isUuid`) and not in the reserved range (`AclSecrets.isReserved`, as Consul's `validateTokenID`), and hashes it (`AclSecrets.hash`) before proposing. The management token links to `AclBuiltins.GLOBAL_MANAGEMENT_ID`.
- **The anonymous token needs nothing:** it is built in.
- **`AclDefaultPolicy`** in `common.acl` is the setting's type for `server.acl.defaultPolicy`, which has no default (proposal 12).
- **Phase 3 changes the runtime** (configuration and startup), so it ends with all three suites.

What Phase 2 left for later phases:

- **Names are compared as written** by the authorizer, as in Consul, while the catalog compares node names regardless of case. Phase 7 decides what a takeover or rename under another case needs (Phase 2's record).
- **A token's grants** come from `AclView.grants(token)`; Phase 4's request context resolves the token and passes them to `AclAuthorizer.decide`.

The list's rules apply: red before green, `mvn install` at the end of each phase, and the full suites for any phase that changes the runtime.

One known false positive for a simple checker: the `lock-contender` trace in `DockerDurableRestartTest` is flagged on its "Exception in thread" line.
