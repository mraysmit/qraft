## 2. How the owner wants the work done

The rules are in [`AGENTS.md`](../AGENTS.md), [`docs/PROJECT_STANDARDS.md`](../docs/PROJECT_STANDARDS.md) and
[`docs/TESTING.md`](../docs/TESTING.md). The ones most often at stake:

- Strict test-first: a failing test, seen to fail for the right reason, before the code.
- The owner commits and pushes. Never add assistant or AI attribution anywhere.
- The suites run on Jenkins once the owner has pushed; start the job and audit its logs
  ([`docs/JENKINS.md`](../docs/JENKINS.md)). When Jenkins cannot be reached, run every suite locally.
- A run is accepted only after its logs are read: any unflagged error line or stack trace is a defect to fix
  ([`docs/TESTING.md`](../docs/TESTING.md#intentional-error-flags-and-log-auditing)).
- A race or an intermittent failure is a defect: find its cause, never retry it away.
- Never remove Docker volumes without listing them and the owner's word.
- Do not stop for go-ahead once a cause and its fix are clear; stop only for a commit, removing Docker volumes or
  reversing a recorded decision. Where options remain, take the recommended one, say so, and record it as reversible.
- Qraft has only "server mode" and "client mode". The working tree is CRLF.
- Task lists and handovers live in `docs-design/` with the date of their last change in the name; a finished list is
  archived to `docs/archive/` without asking.

## 5. Open items

- **What a first release needs.** Every feature of the backlog is built; what remains is shipping: versioning and a
  changelog, the release artifacts, upgrade and compatibility rules between versions, user documentation, a security
  review, a longer soak run. The owner has not chosen.
- **A follower builds every held entry's payload for each AppendEntries**, a heartbeat included
  (`RaftNode.prepareAndPersistFollowerAppend`, the `currentEntryData` passed to `raftlog`'s `AppendPlan.from`), so the
  work grows with the log up to its snapshot. Narrowing it depends on what `AppendPlan` reads.
- **A heartbeat fast path**, as `hashicorp/raft` has, only if a check-quorum step-down caused by a busy follower is
  seen (open-items list, decision 6).
- **Found by the documentation review and not fixed**, for the owner. Each was read in the code; none is shown by a
  test.
  - `/v1/operator/autopilot/health`, `/raft/members`, `/raft/storage`, `/configuration`, `/v1/internal/ui/audit`,
    `/raft/status` and `/v1/operator/raft/configuration` accept `stale`, `consistent`, `index` and `wait` but apply
    none. The API reference says so.
  - Configuration: the shutdown timeouts apply per hook, not in all, as `getShutdownTimeoutMs`'s Javadoc says; type
    errors name the field, not the full key; `null` is absent for some settings and refused for others.
  - `DistributedStateService` (gRPC) does not forward, lists in no fixed order and is not audited: whether it stays or
    is retired is a design question.
  - Docker: `start.ps1` and `start-quick.ps1` work only from `docker/`; every file in `docker/compose/` falls into one
    Compose project, `compose`, so clusters share volumes and `start-quick status` likely misses the server volumes
    (naming the projects changes the volume names of hand-run clusters, whose data would then not be found);
    `network-test` grants `NET_ADMIN` to an image with no `tc` or `iptables`; nothing mounts
    `docker/config/five-node-acceptance/`; neither the jar nor the image carries Qraft's `LICENSE` and `NOTICE`
    (`.dockerignore` leaves them out); `docker/config/client.json` registers its service on the client's own loopback
    port.
  - The empty, untracked `docker/config/agent-acceptance/` carries a retired word; nothing uses it.
- **The old JDK on Jenkins.** `/var/lib/jenkins/workspace/Qraft@tools/sapmachine-jdk-27`, the 27+35 cache, is
  unused once a build has run on 27.0.1.1. Removing it is the owner's call.
- **The JDK on the `mraysmit` workstation** is 27.0.1.1 and whole again: `java -version` prints no class-data
  sharing warning, and the runs since 18:00 on 2026-11-21 left no `.dumpstream` file.
